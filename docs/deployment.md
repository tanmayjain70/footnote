# Deployment

Two services on Render's free tier, one PostgreSQL on Neon. Total cost:
nothing. Total setup: about twenty minutes, most of it waiting for the first
image to build.

Neon rather than Render's own Postgres for two reasons: **Render deletes a
free database after 30 days**, and a portfolio demo that stops working in a
month is worse than no demo; and Neon ships **pgvector**, which the schema
needs, without anything to install.

---

## 1. The database

1. Create a Neon project. Copy the connection string it gives you — that is the
   **owner** role.
2. Open Neon's SQL editor and run
   [`scripts/bootstrap-cloud-db.sql`](../scripts/bootstrap-cloud-db.sql), with
   the password replaced. It creates the `vector` extension and `footnote_app`,
   the low-privilege role the API runs as.

Do not skip step 2. The API asserts at startup that it is not a superuser and
does not own any tables, and will refuse to start otherwise. That check is the
point — see [architecture.md](architecture.md#7-security-and-roles).

Two connection strings come out of this:

```
DATABASE_ADMIN_URL = postgresql+psycopg://<owner>:<pw>@<host>/<db>?sslmode=require
DATABASE_URL       = postgresql+psycopg://footnote_app:<pw>@<host>/<db>?sslmode=require
```

Note `postgresql+psycopg://`, not `postgres://`. Neon hands you the latter;
SQLAlchemy needs the former, and the error if you paste it verbatim names a
missing driver rather than the actual problem.

## 2. The API

From the Render dashboard: **New → Blueprint**, point it at this repository. It
reads [`render.yaml`](../render.yaml) and creates both services.

Fill in the variables marked `sync: false`:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the app-role string from above |
| `DATABASE_ADMIN_URL` | the owner string from above |
| `CORS_ORIGINS` | `https://footnote-web.onrender.com` — after the static site exists. A JSON array works too |
| `ANTHROPIC_API_KEY` | optional — see below |

`JWT_SECRET` is generated by Render and stays stable across deploys. Never
reuse the development value.

### Answers: with a key or without

The blueprint sets `LLM_PROVIDER=stub`: answers are extractive, cost nothing,
and every citation is still verified. To have a hosted model write the answers
instead, set `LLM_PROVIDER=anthropic` and `ANTHROPIC_API_KEY`. The daily budget
inside the app (default $5, editable on the Usage page by the director) caps
what a public demo can spend; the 429 it returns is part of the demo. The
provider only ever receives the eight retrieved passages and the question,
never a whole document.

### The embedding model is in the image

`api/Dockerfile` downloads `BAAI/bge-small-en-v1.5` at build time, so a cold
start after the instance has slept does not fetch 65 MB before it can answer.
The model runs under ONNX Runtime with one thread (`FASTEMBED_THREADS=1`) to
stay inside the free instance's 512 MB. That figure is an expectation from the
model's size, not a measurement on Render; if the instance restarts under
memory pressure, the first thing to try is the next plan up, not a smaller
model — the vectors in the database are tied to this one.

### Seeding runs behind the server

With `DEMO_MODE=true` the entrypoint starts uvicorn first and runs the seeder
in the background once the port answers. Embedding 48 leases — about 1,700
passages — takes a few minutes on a small CPU; a health check that waited for
it would declare the container dead. So for the first few minutes after the
first deploy the API is up, sign-in works, and the Documents page shows leases
arriving one by one. Every boot after that finds the data present and the
seeder exits in a second. `python -m app.demo.seed --force` rebuilds on demand.

## 3. The frontend

Created by the same blueprint. Set:

| Variable | Value |
|---|---|
| `VITE_API_BASE` | `https://footnote-api.onrender.com/api/v1` |

Vite bakes this in at build time, so changing it needs a redeploy, not a
restart.

### One limit that belongs in front of the application

`MAX_UPLOAD_MB` is enforced in the upload handler, and the handler runs after
the server has already received and spooled the body. A declared
`Content-Length` over the limit is refused without reading, but a client that
lies about it has still sent the bytes. On a proxy that fronts the API, set the
same ceiling there — `client_max_body_size 25m` in nginx, or the platform's
equivalent — so an oversized upload is refused at the door rather than after
it has filled a disk.

## 4. Check it

```
curl.exe -s https://footnote-api.onrender.com/api/v1/healthz
curl.exe -s https://footnote-api.onrender.com/api/v1/readyz
```

`/healthz` answers without touching Postgres — that is why Render's health
check points at it. `/readyz` runs `SELECT 1`, so it is the one that tells you
whether the database wiring is right. Then open the frontend and sign in as
`director@hallampryce.demo` with `demo-password`; the header shows whether the
worker is alive and how many jobs are queued.

The smoke test runs against any base URL:

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke-test.ps1 -BaseUrl https://footnote-api.onrender.com
```

---

## The free-tier caveat, stated plainly

The API sleeps after fifteen minutes of inactivity and takes up to a minute to
wake. The login screen says so while it waits, rather than showing a spinner
that looks broken. Anyone reviewing this should know it is a hosting choice,
not a performance characteristic of the application.

## Local development

Needs PostgreSQL 17 **with pgvector**, Python 3.11+, Node 20+.

On Windows without administrator rights — the usual case — the installer's
PostgreSQL has no pgvector and cannot be given one. `scripts\dev-db.ps1
install` downloads the official zip binaries, compiles pgvector with the Visual
Studio Build Tools, initialises a cluster on port 5433 in your user profile,
writes the generated superuser password to `%USERPROFILE%\tools\pgsql17\CREDENTIALS.txt`,
and runs the role bootstrap. It is not a service: `dev-db.ps1 start` after a
reboot.

Otherwise, against a PostgreSQL that already has the extension:

```
set PGSUPERPASSWORD=your-postgres-password
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\bootstrap-db.ps1
```

Then:

```
cd api
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
copy .env.example .env
rem  set JWT_SECRET, and the port in both URLs if you used dev-db.ps1 (5433)
.venv\Scripts\alembic upgrade head
.venv\Scripts\python -m app.demo.seed
.venv\Scripts\uvicorn app.main:app --reload

rem  second terminal
cd web
npm install
npm run dev
```

Then <http://localhost:5173>. The Vite dev server proxies `/api` to port 8000,
so development and production behave the same way with respect to origins.
The first `seed` downloads the embedding model (65 MB) into
`api\.fastembed_cache` and then embeds the corpus; expect a few minutes.
